# 주요 결정과 이유

## 백엔드: pygame-ce (SDL2)

- Qt 없이 가볍게, 창/이벤트/폰트/클립보드/IME 를 SDL 에 맡기고 위젯은 직접 만든다.
- 진짜 터미널(Textual)은 그래프 해상도가 점자 문자 수준이라 제외, 자체 창에서 "TUI 처럼 보이는" 방식 선택.
- macOS 에서 `pygame.Window(allow_high_dpi=True)` 서피스가 실제 2x 로 나오는 것을 확인 (P0).

## 폰트

- 기본 D2Coding: 한글 폭이 영문의 정확히 2.0 배 (16px/32px 모두 실측). 셀 격자가 깨지지 않는다.
- 저장소에 원본 파일 + `D2Coding-OFL.txt`/`LICENSE.md`/`AUTHORS.txt` 포함 (SIL OFL 1.1, 수정 없이 재배포).
- 둥근모(DungGeunMo)는 레트로 룩으로 좋지만 라이선스 출처를 확인하지 못해 포함하지 않았다.
- 모호폭 문자(박스 문자, `° ± µ Ω`)는 1칸으로 본다. 2칸이면 테두리와 단위 표기가 어긋난다.

## 성능 (P0/P2 실측, Apple Silicon, Retina)

| 조건 | 결과 |
|---|---|
| 플롯 3개 x 시리즈 3개, 2400px 폭, aalines 60Hz | CPU ~100% |
| 같은 조건, 일반 lines 30Hz | CPU ~42% (측정용 워커 10% 포함) |
| live_plot 데모 (busy spin 수정 전) | 45fps, CPU 46%, `step()` 6초에 149k 회 |
| live_plot 데모 (수정 후) | 42fps, CPU 35% (워커 11% 포함 → UI ~24%), `step()` 4초에 365 회 |

- 플롯 기본값: 안티앨리어싱 끔, `update_hz=30`, 논리 픽셀 폭 기준 min/max 축약.
- busy spin 원인: 플롯 폴링 시각은 지났는데 fps 상한 전이라 그리지 못하는 동안 대기 시간이 0 이하 → 헛돎.
  대기 시각을 `max(폴링 시각, 다음 프레임)` 으로 잡아 해결.

## 한글 IME 보정

`tests/fixtures/ime_macos_2set.json` (macOS 두벌식 실제 기록) 에서 확인한 것:

| 현상 | 보정 |
|---|---|
| 조합 중 Enter/Tab/화살표: KEYDOWN 이 확정(TEXTINPUT) **보다 먼저** 온다 | KEYDOWN 전에 조합 글자를 직접 확정, 뒤따르는 같은 확정/조합 반복은 버림 |
| 조합 중 Backspace: 자모를 지우지 않고 조합 글자를 **확정해 버린다** | 확정을 버리고 마지막 자모만 뺀 글자를 넣음 ("한"→"하") |
| 조합 중 스페이스/마침표: "철 " 처럼 붙여서 확정 | 건드리지 않음 |
| 한글 입력 상태의 글자 KEYDOWN 이름이 `""` | scancode 로 영문 키 이름 복원 (단축키/니모닉/메뉴 선택 문자) |
| 조합 중 포커스 이동/클릭 | 이전 위젯에 확정 후 이동 |

Windows/Linux 는 기록이 없다. 순서가 달라도(확정이 먼저 오면) 보정이 개입하지 않도록 만들어 두었다.

## 화면 스타일

- 기본 테마 **mono**: 순수 검정 배경, 흰/회색 UI. 그래프 시리즈와 오류 색만 컬러 (흑백이면 시리즈 구분 불가).
- 박스 버튼 (mono 기본): 레이아웃은 3줄이지만 테두리를 글자 쪽으로 당겨 보이는 높이 ≈ 1.6줄
  (`boxdraw.EDGE_INSET = 0.7`, Retina 14pt 에서 ~111px → ~59px). 테두리 셀은 바깥=배경, 선, 안쪽=채움색 3색을 `FILL` 속성으로 표현.
  - 기본: 가는 회색 선 / 마우스 올림: 가는 흰 선 / 포커스: 굵은 흰 선 + 회색 채움 / 누름: 굵은 흰 선 + 밝은 채움.
  - 포커스와 hover 모양을 다르게 해서 Enter 가 어디로 가는지 보이게 했다.
- macOS 에서 비활성 창 첫 클릭이 버려지는 문제: `SDL_MOUSE_FOCUS_CLICKTHROUGH=1`.

## 대화상자는 콜백 방식

Qt `exec()` 처럼 블로킹하지 않는다. 이벤트 루프가 멈추면 시리얼 수신/그래프 갱신도 멈추기 때문. 결과는 `on_result(index)`.

## 저장소 구조와 이름

- 한 저장소에 라이브러리(`retro-ui/`) + 앱(`baram-term/`). 함께 바뀌는 지금은 편하고, 나중에
  `git subtree split --prefix=retro-ui` 로 이력째 분리할 수 있다. 라이브러리는 앱을 import 하지 않는다.
- 이름 비교 (PyPI 에서 세 이름 모두 비어 있음을 확인):
  - `baram-term` ✔: 개인 아이디(baram) 기반이라 겹치지 않고 검색이 잘 된다. 쓰임새는 부제로 보완
    ("펌웨어 CLI 시리얼 터미널").
  - `retro-term`: 유명한 `cool-retro-term`(CRT 느낌 셸 터미널)과 헷갈리고 기능이 드러나지 않는다.
  - `cli-term`: 뜻은 잘 드러나지만 일반 단어라 묻히고, HEX/그래프 같은 기능에는 좁다.

## 다국어

baram-term 첫 버전부터 `tr("key")` + 언어별 JSON 구조로 만든다. 문자열이 코드에 흩어진 뒤에 바꾸는 비용이 훨씬 크다.
레이아웃은 글자 폭 기반 자동 크기라 언어별 길이 차이에 버틴다. 터미널에 보이는 펌웨어 출력은 번역하지 않는다.

| 대화상자 버튼은 같은 폭, 가운데 정렬 | "OK" 와 "Cancel" 처럼 길이가 다르면 오른쪽 정렬 버튼 줄이 한쪽으로 쏠려 보였다 |

## 2026-09-15 매크로 막대와 저장소 소개

| 결정 | 이유 |
|---|---|
| 개성 기능은 HEX 보기가 아니라 **매크로 막대부터** | 대상이 텍스트 CLI 라서 매크로는 매일 쓰고 HEX 는 문제가 있을 때만 쓴다 |
| F10 은 매크로 키에서 **아예 뺀다** (메뉴 키 그대로) | F10 = 메뉴는 오래된 약속이고 메뉴가 더 기본 기능이다. 처음에는 'F10 칸은 클릭으로만 보낸다'로 뒀는데, 등록 창에서 키를 고르게 되면서 고를 수 있는데 눌러도 안 먹는 칸이 되어 버렸다. 고를 수 없게 빼서 매크로는 최대 11개 (설정에 F10 이 적혀 있으면 남는 번호로 옮긴다) |
| 슬롯은 `"이름=명령"` 문자열 목록으로 저장 | 설정 파일을 손으로 고칠 수 있고, 기존 `_valid` 의 `list[str]` 검사에 그대로 걸린다. `=` 가 없으면 명령이 곧 이름 |
| 막대는 등록된 매크로만 빈 칸 없이 늘어놓고 **맨 끝에 `+`** 를 둔다 | 12칸을 늘 그리면 폭만 먹는다. 빈 칸 대신 `+` 하나로 등록한다 |
| **F 번호를 매크로가 들고 있다** (`"F5\|이름=명령"`), 등록 창에서 고른다 | 처음에는 목록 순서를 번호로 썼는데, 가운데를 지우면 뒤 매크로의 번호가 밀려 손에 익은 키가 바뀌었다. 키를 값으로 들고 있으면 지워도 남은 번호가 그대로고, 막대는 번호 순으로 그리되 빈 칸은 안 그린다 (`F1 F3 F7` 처럼 뛸 수 있다) |
| 등록 창의 키 목록에서 **이미 쓰는 번호는 뺀다** (고치는 중인 번호는 남긴다) | 겹치는 번호를 고를 수 있으면 둘 중 하나가 밀려난다. 아예 못 고르게 하는 편이 설명이 필요 없다 |
| 설정의 키 앞머리는 `F5\|` | 손으로 고칠 수 있는 한 줄 문자열을 유지하면서(`_valid` 의 `list[str]` 그대로) 명령에 들어갈 일이 거의 없는 구분자다. 앞머리가 없으면 남는 번호를 앞에서부터 붙여 준다 |
| 폭이 모자라면 뒤쪽 버튼을 통째로 뺀다 (반쪽으로 자르지 않는다) | 잘린 버튼은 누를 수 있는지 헷갈린다. `MacroBar.layout_children` 에서 안 들어가는 버튼에 빈 자리를 준다 |
| 등록된 칸은 채운 회색 버튼, 빈 칸은 글자만 흐리게 | 그래프의 지우기/정지 버튼과 같은 결. 강조색으로 채우니 막대가 화면에서 너무 튀었다 |
| 매크로 버튼도 포커스를 가져가지 않는다 | 그래프 버튼과 같은 이유: 마우스용이고 키보드 입력은 터미널에 남아야 한다 |
| README 그림은 손으로 캡쳐하지 않고 스크립트로 만든다 | `docs/images/make_*.py` 가 `SDL_VIDEODRIVER=dummy` 로 앱을 실제로 돌려 저장한다. 화면이 바뀌면 다시 돌리면 되고, 회사 정보가 섞일 일이 없다 |
| 이름이 길면 버튼에서 줄이고(`F1 nvs set wifi_…`) 명령은 그대로 보낸다 | 한 칸이 막대를 통째로 먹었다. 줄인 이름 때문에 무엇을 보내는지 모르게 되니 hover 툴팁으로 전체 명령을 보여준다 |
| 폭이 모자라면 **숨기지 말고 이름부터 줄여** 모든 칸을 보여준다 | 칸을 감추면 F 키는 되는데 버튼만 없어 헷갈린다. 이름을 줄여도 보낼 명령은 그대로고 툴팁에 전체가 나온다. 번호만 남겨도(`F12`) 모자랄 때만 뒤를 접고 `+3` 으로 알린다 |
| 이름을 4칸 미만으로 줄여야 한다면 아예 번호만 보여준다 | `F1 he…` 는 자리만 먹고 무엇인지 알려주지 못했다. 그럴 바엔 `F1` 로 짧게 두고 툴팁으로 확인하는 편이 낫다 |
| 오른쪽 클릭은 **수정 / 삭제 팝업 메뉴** (왼쪽 클릭은 전송) | 왼쪽 클릭을 전송에 썼으니 고칠 길이 따로 필요하다. 바로 편집 창을 열면 지우기가 그 창 안에 숨는다. 빈 칸은 지울 것이 없어 메뉴 없이 등록 창을 연다 |
| 툴팁은 매크로 전용이 아니라 retro-ui 의 기능으로 | 위젯에 `tooltip` 문자열만 넣으면 App 이 띄운다. 상태줄 항목·범례처럼 좁아서 줄여 쓰는 곳이 이미 여럿이다 |
| 툴팁은 커서 밑이 아니라 위젯 **위**에 띄운다 | 커서와 겹치면 hover 가 툴팁으로 넘어가면서 떴다 사라졌다 한다 |
| 배너 로고는 손으로 그린 글꼴 대신 **원본 로고 이미지**를 도트로 줄여 쓴다 | 진짜 로고 모양이 그대로 나온다. `tools/logo_from_image.py` 로 다시 만들고 결과는 값으로 박아 둔다 (실행할 때 이미지를 읽지 않고, PyInstaller 로 묶을 때도 편하다) |
| 원본 왼쪽 **마크는 빼고 "BARAM" 글자만** 쓴다 | 마크는 선이 가늘어서 도트로 줄이면 선이 끊겨 깨져 보였다 (실제로 보고 확인). 17도트 이상이면 살지만 배너가 74칸으로 커진다. 글자는 획이 굵어 작게 줄여도 버틴다 |
| 줄이는 배율은 **정수**만 (지금 2배: 126x24 픽셀 -> 63x12 도트) | 2.18픽셀처럼 어중간하게 줄이면 같은 굵기의 획이 3도트/4도트로 갈려 A, M 의 좌우 대칭이 깨진다 (실제로 보고 확인). 도트가 원본 픽셀 2x2 에 딱 맞으면 대칭이 그대로 남는다 — `test_symmetric_letters_stay_symmetric` 가 지킨다 |
| 매크로 버튼은 글자 좌우 여백 1칸 (기본 버튼은 2칸) | 12칸까지 늘어서는 줄이라 칸마다 4칸씩 쓰면 너무 넓다. Button 에 `padding` 을 두어 다른 버튼은 그대로 뒀다 |
| 대화상자 라벨 폭은 그 창에서 가장 긴 라벨에 맞춘다 | 고정값(6칸)으로 두었더니 en 에서 `Command`(7칸)/`Name`(4칸) 길이가 달라 입력칸 시작 열이 어긋났다 (ko 는 둘 다 4칸이라 우연히 맞았다) |
| 대화상자의 입력칸 사이는 한 줄 띄운다 | 붙여 놓으면 어두운 입력 배경이 이어져 한 칸처럼 보였다 |
| 로고 흰색은 순백(ANSI 15) 대신 (205,205,205) | 검은 배경에서 순백은 너무 쨍하다 |

SDL 이 알려주지 않는 수정키(fn)가 섞인 조합은 뺀다 |
| 터미널 영문 입력 옵션, **기본 켜짐** | 펌웨어 CLI 명령은 영문이라 한글로 쓰다 터미널에 올 때마다 한/영을 바꾸는 게 불편했다. 터미널에 포커스가 있을 때만 IME 를 끄고 글자는 물리 키 위치(미국 배열) + Shift + Caps Lock 으로 직접 만든다. 검색창·대화상자는 그대로 한글 입력. Option 조합 특수문자는 만들지 않는다. retro-ui `Terminal.ascii_input` 기본은 꺼짐으로 둔다 (범용 위젯은 IME 가 기본이 자연스럽다) |
| Caps Lock 은 `KeyEvent.caps` 로 따로 둔다 (`Mod` 에 넣지 않는다) | `Mod` 에 넣으면 수정키를 정확히 비교하는 곳(단축키, 입력 전환 조합)이 Caps Lock 이 켜진 동안 모두 어긋난다 |
| 윈도우에서는 SDL 에 DPI 를 알린다 (`SDL_WINDOWS_DPI_AWARENESS=permonitorv2`, `SDL_WINDOWS_DPI_SCALING=1`) | Windows 11 실측: 화면 배율이 100% 가 아니면 글자가 흐렸다. DPI 를 모르는 앱은 윈도우가 100% 로 그린 화면을 늘려 보여준다. `allow_high_dpi` 는 macOS 에만 효과가 있다. DPI_SCALING 을 켜면 창 좌표는 배율 단위, 표면은 실제 픽셀이라 macOS Retina 와 같은 경로(표면 폭 / 창 폭 = 배율, 폰트 다시 열기)를 그대로 쓴다. 사용자가 환경변수로 준 값은 덮어쓰지 않는다 |
| 메뉴 맨 앞에 **파일**을 두고 포트 메뉴는 연결·끊기·포트 설정만 | 로그 저장·끝은 포트가 아니라 파일 메뉴에 있을 항목이다 (CoolTerm, Tera Term 도 파일이 맨 앞). 언어 선택을 둘 자리도 필요했다. 단축키(Ctrl-A L, X 등)는 그대로 |
| 화면 언어는 파일 메뉴에서 고르고 **다음 실행부터** 적용한다 | 메뉴와 라벨은 만들 때 한 번 번역된다. 바로 바꾸려면 스크롤백·연결·그래프 상태를 옮겨 담아 화면을 다시 만들어야 해서 저장만 하고 안내한다. Windows 11 한국어 환경에서 영어로 바꿀 방법이 없었다 (실행 인자 `--lang` 뿐) |
| 언어 이름은 각 언어로 적는다 ("한국어", "English") | 화면이 모르는 언어로 되어 있어도 자기 언어를 찾을 수 있어야 한다 |
| 화면 언어 기본은 **영어** (시스템 로케일을 보지 않는다) | 사용자 결정. 예전에는 로케일이 ko* 면 한국어로 시작했다. 이제 한국어는 파일 메뉴에서 고르고 설정에 저장한다. `--lang`, `BARAM_TERM_LANG` 은 그대로 우선한다 |


## 2026-09-16 배포와 포트 설정 창

| 결정 | 이유 |
|---|---|
| baram-term 은 retro-ui 를 **git URL 로 의존**한다 (`retro-ui @ git+…#subdirectory=retro-ui`) | retro-ui 가 PyPI 에 없어서 `pipx install` 이 실패했다. 로컬 개발은 `[tool.uv.sources]` 가 이 줄을 덮어써 editable 로 남는다. 평범한 pip 은 URL 과 로컬 경로를 충돌로 보므로 **두 줄로 나눠** 설치한다 (baram-term 먼저, retro-ui 로 덮어쓰기). PyPI 에 올리려면 retro-ui 를 먼저 올리고 이 줄을 버전으로 바꿔야 한다 — PyPI 는 직접 URL 참조를 거부한다 |

| 마우스로만 쓰는 버튼은 포커스를 받지 않는다 (포트 설정 Refresh) | 누를 때 `► ◄` 가 붙어 눌린 것처럼 보이지 않았다. 그래프·HEX·매크로 버튼은 이미 그렇게 돼 있었는데 이 버튼만 빠져 있었다 |
| 테스트는 **신호를 쏘지 말고 실제로 눌러 본다** | 새로고침 테스트가 `clicked.emit()` 으로 신호만 쏴서 마우스 경로(hit-test → down → up)가 한 번도 검증되지 않았고, 그래서 `► ◄` 버그가 테스트를 통과한 채 v0.1.0 까지 갔다. 같은 이유로 "목록에 보이는가" 도 화면 글자로 확인한다 — 항목을 넣어 놓고 `visible_rows` 가 모자라 스크롤해야 보이는 상태를 271개 테스트가 통과시켰다 |

|---|---|
| 외부 제어는 **창마다 소켓 하나** (`~/.baram-term/ctl/<pid>.sock`) | 창을 여러 개 띄우는 것은 이미 하던 일이다. 하나를 나눠 쓰면 어느 창이 주인인지 정해야 하고, 그 창을 닫으면 나머지가 제어를 잃는다. pid 이름이면 죽은 뒤 남은 소켓도 pid 로 정리할 수 있다 |
| 대상이 **하나로 좁혀지지 않으면 아무것도 보내지 않는다** (종료 코드 5) | 보드가 여러 개 꽂힌 자리에서 명령이 엉뚱한 보드로 가면 되돌릴 수 없다. 자동화가 후보 목록을 보고 고르게 하는 편이 안전하다 |
| BLE 주소는 **이름 기준** (`ble://이름[#꼬리표]`), 장치 주소는 대체 수단 | macOS 는 MAC 대신 PC 마다 다른 CoreBluetooth UUID 를 준다. 주소로 저장하면 같은 보드도 다른 PC 에서 못 찾는다. 이름은 어디서나 같고, 같은 이름은 광고 제조사 데이터 끝 4바이트로 가른다 |
| BLE 검색은 **NUS 를 광고하는 것만** | 둘레의 이어폰·시계·TV 까지 나오면 고르기 어렵고, 열어도 쓸 수 없다. 광고에 UUID 를 싣지 않는 보드가 나오면 그때 "전부 보기" 를 더한다 |
| BLE 열기는 **UI 스레드 밖에서**, 찾는 즉시 스캔을 멈춘다 | 처음에는 UI 스레드에서 열었더니 창이 5초 넘게 멈췄고, 자동 재연결(1초 간격)이 그것을 반복했다. `discover()` 는 장치를 봐도 정해진 시간을 꽉 채운다 — 연결에는 `find_device_by_filter` 를 쓴다. 창은 0.04초에 뜨고 상태줄에 "찾는 중" 이 남는다 |
| `ctl resume` 은 **연결을 기다리지 않고** 답한다 (`connecting: true`) | BLE 는 여는 데 몇 초가 걸려 제어 요청(5초)이 시간 초과가 났다. 기다리는 일은 부른 쪽이 `status` 나 `wait` 로 한다 |
| **마지막 연결 상태를 기억한다** (`connected`) | 일부러 끊고 종료한 것과 연결된 채 종료한 것이 다음 실행에서 똑같이 자동 연결로 보였다. 뽑혀서 끊긴 것은 사용자가 끊은 것이 아니므로 자동 재연결을 그대로 둔다 |
| "BLE 장치 사용" 은 **연결까지 막는다** | 처음에는 대화상자와 검색만 막았더니, 껐는데도 저장된 `ble://` 주소로 다음 실행에 다시 붙었다. 끄면 붙어 있던 것도 끊는다 |
| **DFU(SMP)는 넣지 않는다** (2026-09-20 사용자 결정) | 시리얼 DFU 는 SMP(VCOM0)와 CLI(VCOM1)가 다른 포트라 baram-term 이 할 일이 없고, BLE 는 `ctl release` → 외부 도구 → `resume` 으로 이미 된다. 직접 구현하면 SMP 헤더 + CBOR + img/os 그룹 + 프레이밍까지 700줄 안팎이고 사양을 계속 따라가야 한다. 넣는다면 BLE 한정이다 — NUS 와 SMP 는 한 연결 위에 공존하므로 창을 닫지 않고 업데이트하는 것이 baram-term 만 할 수 있는 일이다. 그때도 CBOR 을 직접 짜지 않고 `smpclient` 를 선택 의존성으로 쓴다 |
